Step 03 / 09 · 10 minutes

Plan a safe change

The connection pattern stays the same. The SQL and result-handling method change.

The familiar lifecycle still applies

Prepare settings and validated values, create the connection object, open it, configure a command and its parameters, execute it, inspect the result and leave the scope to release resources.

Required resultMethodWhat your code receives
One valueExecuteScalarAsync()The first column of the first returned row.
RowsExecuteReaderAsync() + ReadAsync()A reader that advances through rows.
A simple INSERT / UPDATE / DELETEExecuteNonQueryAsync()An integer affected-row count for our statements.
NonQuery does return a value

It does not return a result set of rows. In this practical, it returns the affected-row count. Stored procedures, triggers and SET NOCOUNT can change row-count behavior; we are using simple single-statement commands here.

C# · decimal parameter example
SqlParameter feeParameter = command.Parameters.Add("@fee", SqlDbType.Decimal);
feeParameter.Precision = 8;
feeParameter.Scale = 2;
feeParameter.Value = 75.50m;
SettingMeaning
Precision = 8Up to eight digits in total.
Scale = 2Two digits after the decimal point. This schema accepts fees from 0 to 999999.99.
75.50mThe m suffix makes this C# literal a decimal.
NVarChar, 100The string parameter size matches CourseName’s maximum length.
Values travel separately

Keep placeholders in SQL and add values through Parameters. A name such as Trainer's SQL Workshop is data; its apostrophe does not become SQL syntax. Parameters represent values, not table names or entire WHERE clauses.

C# · replace the matching TODO placeholder
await using (SqlConnection connection = new SqlConnection(connectionString))
{
    await connection.OpenAsync();
    const string sql = @"INSERT INTO dbo.Courses
        (CourseId, CourseName, CreditHours, InstructorId, Fee, StartDate, IsActive)
        VALUES (@courseId, @courseName, @creditHours, @instructorId,
                @fee, @startDate, @isActive);";

    await using SqlCommand command = new SqlCommand(sql, connection);
    command.Parameters.Add("@courseId", SqlDbType.Int).Value = courseId;
    command.Parameters.Add("@courseName", SqlDbType.NVarChar, 100).Value = courseName;
    command.Parameters.Add("@creditHours", SqlDbType.Int).Value = creditHours;
    command.Parameters.Add("@instructorId", SqlDbType.Int).Value = instructorId;
    SqlParameter feeParameter = command.Parameters.Add("@fee", SqlDbType.Decimal);
    feeParameter.Precision = 8;
    feeParameter.Scale = 2;
    feeParameter.Value = fee;
    command.Parameters.Add("@startDate", SqlDbType.Date).Value = startDate;
    command.Parameters.Add("@isActive", SqlDbType.Bit).Value = isActive;

    int affectedRows = await command.ExecuteNonQueryAsync();
    Console.WriteLine($"Rows inserted: {affectedRows}");
}

BROWSER SIMULATION · row targeting and affected counts

Which row changes?

Insert course 190 first, or add it to the browser simulation. SQL Server has a separate state.
No match is not an exception

For this simple command, a valid but missing key produces 0 affected rows. It is different from a connection failure or a constraint error. SQL Server can count a matched row even when its assigned values already equal the stored values.

The foreign key protects the relationship

Course 101 appears in Enrollments. The supplied foreign key uses NO ACTION deletion behavior. SQL Server rejects the parent deletion. Deleting an unused draft is our task; deleting enrollment history or enabling cascade deletion is not part of this workflow.

Handling errors is different from releasing resources

Supplied error handling · already present after the try block
catch (SqlException ex)
{
    Console.WriteLine($"SQL Server error {ex.Number}: {ex.Message}");
    if (ex.Number == 2601 || ex.Number == 2627)
        Console.WriteLine("This key already exists.");
    else if (ex.Number == 547)
        Console.WriteLine("A relationship or CHECK rule prevented this change.");
    else
        Console.WriteLine("Check the connection, database setup and SQL command.");
}

One SqlException catch handles many SQL failures. Its number and message identify the cause. Error 547 can represent a foreign-key or CHECK violation, so inspect the named constraint. The other catches from the live session remain in the supplied app.

Step 07 / 09 · 12 minutes

Read a richer, filtered report

Three parameters and seven columns reuse the reader pattern. Two result cells can contain NULL.

Business requirement

For a selected programme, show enrollments in active courses with a fee at or above a chosen minimum. Include the course instructor, fee, start date and grade. Display clear text when an instructor is unassigned or a grade has not been recorded.

TODO 04

Select activity 4. The five-table SQL is supplied below. Adapt the familiar parameter/reader pattern; focus on the three filters and two nullable result columns.

Supplied SQL · read the joins before pasting the report block
SELECT s.FullName AS StudentName, p.ProgramName,
        c.CourseName, i.FullName AS InstructorName, c.Fee, c.StartDate, e.Grade
        FROM dbo.Programs AS p
        INNER JOIN dbo.Students AS s ON s.ProgramId = p.ProgramId
        INNER JOIN dbo.Enrollments AS e ON e.StudentId = s.StudentId
        INNER JOIN dbo.Courses AS c ON c.CourseId = e.CourseId
        LEFT JOIN dbo.Instructors AS i ON i.InstructorId = c.InstructorId
        WHERE p.ProgramId = @programId
          AND c.Fee >= @minimumFee
          AND c.IsActive = @isActive
        ORDER BY s.StudentId, c.CourseId;
Why LEFT JOIN for the instructor?

We want to keep an enrollment even when its course has no assigned instructor. LEFT JOIN retains that row and returns NULL for InstructorName. Grade can also be NULL because no grade has been recorded. NULL does not mean a zero grade.

    ? "Unassigned" : reader.GetString(3);

    ? "Not graded" : reader.GetDecimal(6).ToString("0.00");

IsDBNull checks the current result cell. ToString("0.00") formats an existing decimal for display; it does not turn a database NULL into a decimal. When sending an optional scalar value to SQL in future work, use DBNull.Value, not a display label.

Reveal the reference implementation
C# · replace the matching TODO placeholder
await using (SqlConnection connection = new SqlConnection(connectionString))
{
    await connection.OpenAsync();
    const string sql = @"SELECT s.FullName AS StudentName, p.ProgramName,
        c.CourseName, i.FullName AS InstructorName, c.Fee, c.StartDate, e.Grade
        FROM dbo.Programs AS p
        INNER JOIN dbo.Students AS s ON s.ProgramId = p.ProgramId
        INNER JOIN dbo.Enrollments AS e ON e.StudentId = s.StudentId
        INNER JOIN dbo.Courses AS c ON c.CourseId = e.CourseId
        LEFT JOIN dbo.Instructors AS i ON i.InstructorId = c.InstructorId
        WHERE p.ProgramId = @programId
          AND c.Fee >= @minimumFee
          AND c.IsActive = @isActive
        ORDER BY s.StudentId, c.CourseId;";

    await using SqlCommand command = new SqlCommand(sql, connection);
    command.Parameters.Add("@programId", SqlDbType.Int).Value = programId;
    SqlParameter feeParameter = command.Parameters.Add("@minimumFee", SqlDbType.Decimal);
    feeParameter.Precision = 8;
    feeParameter.Scale = 2;
    feeParameter.Value = minimumFee;
    command.Parameters.Add("@isActive", SqlDbType.Bit).Value = isActive;

    await using SqlDataReader reader = await command.ExecuteReaderAsync();
    bool found = false;
    while (await reader.ReadAsync())
    {
        found = true;
        string studentName = reader.GetString(0);
        string programName = reader.GetString(1);
        string courseName = reader.GetString(2);
        string instructorName = reader.IsDBNull(3) ? "Unassigned" : reader.GetString(3);
        decimal courseFee = reader.GetDecimal(4);
        DateTime startDate = reader.GetDateTime(5);
        string grade = reader.IsDBNull(6) ? "Not graded" : reader.GetDecimal(6).ToString("0.00");
        Console.WriteLine($"{studentName} | {programName} | {courseName} | {instructorName} | {courseFee:0.00} | {startDate:yyyy-MM-dd} | {grade}");
    }
    if (!found) Console.WriteLine("No enrollments match these filters.");
}

Step 08 / 09 · 6 minutes

See the mapping work an ORM can reduce

More fields and relationships expose maintenance work, not a limit on what SQL or ADO.NET can do.

A new application requirement

Another part of the application wants a Course object containing its ID, name, instructor reference, fee, start date and active flag. A printed line is no longer enough.

With ADO.NET, we explicitly read columns and assign values to object properties. As several screens or operations need the same data, repeated mapping and parameter code must stay aligned with the schema.

CONCEPT SIMULATION · mapping work, no EF Core execution

From a row to an object

Work you have seenWhat EF Core can provide later

Why learn this foundation first?

EF Core is an object-relational mapper. It reduces much of the repetitive data-access code, but it still uses database providers and SQL. It does not remove the need to understand keys, constraints, parameterized values, result shapes or query behavior. It is not automatically faster than well-written SQL.

Today’s boundary

This is an explanation of the work an ORM can reduce, not an EF Core implementation. There is no EF package or DbContext in this starter. You are not required to write object-graph mapping, transactions or stored procedures to complete the introductory ADO.NET foundation.
